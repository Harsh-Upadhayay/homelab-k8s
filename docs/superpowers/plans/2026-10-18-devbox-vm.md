# Devbox VM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Execution mode for THIS plan: learning mode, inline.** Each task is tagged **[Operator]** (the
> operator writes it; the assistant guides, reviews, fixes small issues and explains the concept)
> or **[Assistant]** (mechanical work done directly, with a short explanation). Destructive steps
> are marked ⚠️ and need the operator's explicit go-ahead at the time.

**Goal:** Replace the in-cluster `workbench` devbox with a Proxmox VM running code, agents and per-project Docker Compose stacks, then retire the workbench.

**Architecture:** Terraform creates the VM on `pve-dell` and shrinks `k3s-worker-1`'s RAM to pay for it; Ansible configures it (`tailscale_host` + new `devbox` role); a cluster-admin ServiceAccount gives it `kubectl` over the LAN. Code, `$HOME` and datastore files are streamed from the old pod/PVCs to the VM; after a soak, the workbench and all its support machinery are deleted.

**Tech Stack:** Terraform (bpg/proxmox), Ansible, Ubuntu 26.04 cloud-init, Docker Engine + Compose, Tailscale, k3s v1.36.2, Argo CD, Longhorn.

**Spec:** `docs/superpowers/specs/2026-10-18-devbox-vm-design.md`

## Global Constraints

- `pve-dell` RAM never overcommitted: worker-1 `memory = 18432`, devbox `memory = 10240` (ADR-0020).
- worker-1 keeps `cores = 14`; devbox `cores = 8` → 22 vCPU on 14 threads, accepted (D2).
- Devbox disk: 150GB on `local-lvm` (Dell external SSD), `discard = "on"`. Never `nvme0n1` (ADR-0022).
- Every version pinned (Docker, Compose plugin, mise, kubectl `v1.36.2`, helm, neovim).
- Devbox is NOT a k3s node and NOT an entry in `var.workers`.
- VM user `harsh` (uid 1000 — verified on k3s-worker-1), key `~/.ssh/id_ed25519`.
- Tailnet: unmodified `tailscale_host` role, `tailscale_auth_key_reusable`, untagged, MagicDNS name `devbox`, plain OpenSSH + mosh (UDP 60000–61000).
- Cluster-admin: SA `devbox-admin` in `kube-system`, CRB → `cluster-admin`, token Secret, server `https://192.168.1.21:6443`.
- Code at `/workspace/<dir>`; datastore files at `/srv/devdata/<project>/<service>`.
- Datastore digests (re-verify in Task 1): mysql `sha256:679e7e924f38a3cbb62a3d7df32924b83f7321a602d3f9f967c01b3df18495d6`, qdrant `sha256:12364fe851b9f17356fc88189fc06d1b521262e04659ec7345975b00c9246a10`, rabbitmq `sha256:e582c0bc7766f3342496d8485efb5a1df782b5ce3886ad017e2eaae442311f69`.
- pwm data is not migrated (loss accepted).
- Repo changes go via branch + PR; no deletion before the soak (Task 8) passes.

## Review Focus

1. **`terraform plan` proposes replacing `k3s-worker-1`** (`-/+`) instead of an in-place memory update — would destroy the worker and its 650GB Longhorn disk. Task 2 must show `~ update in-place` for worker-1 and `+ create` for the devbox, nothing else.
2. **A datastore pod restarting before its digest is captured** (worker-1 reboot pulls a newer `qdrant:latest`/`rabbitmq:3-management`) — Task 1 captures digests and scales datastores to 0 *before* Task 2's apply.
3. **The copy silently dropping something irreplaceable** — an ignored `.env`, `kiroku/data`, symlinks, or uid 999 ownership on datastore files. Task 5 verifies per-directory file counts and ownership against the source.
4. **The Mac can't actually work on the VM** — tailnet policy blocks tcp/22 or udp/60000–61000, agent forwarding missing so `git push` fails. Task 3 and Task 7 verify each path explicitly.
5. **Deleting a PVC with `reclaimPolicy: Delete` before the soak passes** — Task 9 is gated on Task 8 and confirms each destructive step.
